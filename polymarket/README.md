# polymarket — 预测市场研究模块

把 **Polymarket**（去中心化预测市场）作为第三种市场类型接入统一研究框架，
用于检验**市场有效性**并寻找系统性定价偏差。

> 与 `factors/`（A股因子选股）、`crypto/`（加密资金费套利）并列 ——
> 同一套研究流程，适配三个结构完全不同的市场。

---

## 为什么做这个

预测市场的价格**直接就是概率**（0.37 = 市场认为 37% 概率），
比股票价格更容易检验定价效率：

> **如果市场有效，则「价格 0.10 的合约」应该在长期中有 10% 的概率结算为 1。**

这是一个可以直接证伪的命题。

---

## 数据规模（实测）

| 项 | 数值 |
|---|---|
| 赛事目录 | 473 个联赛/项目（含电竞、网球、足球、篮球等） |
| 已结算市场 | 894,913 个 |
| 累计成交额 | $211 亿 |
| 建模数据集 | 74,242 行 / 18,737 个市场 |
| 价格序列 | 日频（部分支持小时频） |

## 研究结论

### 方法

对每个已结算市场，在**结算前 N 天**取一个价格观察点：

```
price    = 该时点的隐含概率（token0 价格）
outcome  = 最终是否胜出（1/0）
edge     = 实际胜率 - 平均价格
         → 买入 YES 的每 $1 期望值
```

### ⚠️ 关键陷阱：样本构成偏差

**初版分析发现问题：不同观察时点的市场集合完全不同。**

```
观察时点   有价格的市场数
30 天前     2,768   (15%)
21 天前     5,917   (32%)
14 天前     6,702   (36%)
 7 天前    15,740   (84%)
 3 天前    18,726   (100%)
 1 天前    18,737   (100%)
```

体育市场大多只存在几天，**只有长周期市场（赛季期货、锦标赛）才有 30 天前的价格**。

**直接比较各时点的"偏差" = 拿苹果比橘子。** 初版因此得出「中档偏差 +5%~+9%」的错误结论。

### 修正后的结论

**只保留在所有 6 个时点都有价格的同一批市场（2,768 个）：**

| 观察时点 | 平均价格 | 实际胜率 | 偏差 |
|---|---|---|---|
| 30 天前 | 0.211 | 0.209 | −0.26% |
| 21 天前 | 0.198 | 0.209 | +1.06% |
| 14 天前 | 0.215 | 0.209 | −0.61% |
| 7 天前 | 0.203 | 0.209 | +0.57% |
| 3 天前 | 0.203 | 0.209 | +0.62% |
| 1 天前 | 0.205 | 0.209 | +0.41% |

**偏差全部在 ±1% 以内，符号随机跳动 —— 这是"定价有效"的典型形态。**

### 唯一残存的弱信号

分档看，**只有样本量 ≥200 的档位可信**：

| 价格区间 | 7天偏差 | 3天偏差 | 1天偏差 | 样本量 |
|---|---|---|---|---|
| 0.00-0.05 | −0.06% | −0.18% | −0.16% | ~1300 |
| 0.05-0.10 | −1.05% | +0.83% | +0.03% | ~290 |
| **0.10-0.15** | **−2.20%** | **−2.47%** | **−2.94%** | **~225** |
| 0.95-1.00 | +1.12% | +1.05% | +0.98% | ~90 |

**价格 0.10-0.15 的合约被高估约 2~3%，且三个时点一致。**

### 结论：**不构成可交易机会**

| 障碍 | 数值 |
|---|---|
| 理论边际 | +2~3% |
| 平台费率 | `rate: 0.05`（sports_fees_v3） |
| 买卖价差 | 0.001~0.01（对 0.10 价格的合约即 1%~10%） |
| 样本量 | 仅 ~225，且只覆盖单一价格档 |

**边际不足以覆盖交易成本 + 样本量不足。**

**这是一个负面结果，但它是有价值的负面结果** —— 用几小时零成本验证，
避免用真金白银去试一个不成立的想法。

## 模块结构

```
polymarket/
├── config.py     路径与 API 端点（支持 PM_DATA_DIR 环境变量）
├── fetch.py      数据采集
│                 · catalog  拉 473 个联赛目录（含 primaryTagId、官方结算源）
│                 · markets  按联赛 tag_id 拉已结算市场
│                 · prices   按 clobTokenId 拉日频历史价格（8 线程并发）
├── dataset.py    构建建模表：每个市场 × 每个观察时点(30/21/14/7/3/1天)
├── analyze.py    分档校准分析（隐含概率 vs 实际胜率）
└── validate.py   受控对照验证（只保留全时点都有价格的市场）
```

### 数据获取的技术要点

1. **`/sports` 端点**返回 473 个赛事目录，每个带 `primaryTagId` 可用于筛选事件
2. **二元市场只需拉一个 token 的价格**（`price(tok1) ≈ 1 − price(tok0)`）→ 速度翻倍
3. **RSS/feed 自带全文时优先使用**，可绕过部分站点的 Cloudflare 封锁
4. **并发采集**：8 线程从 3.3 req/s 提升到 ~280 req/s（实测 32 倍）

## 快速开始

```bash
# 1) 拉赛事目录（473 个）
python -m polymarket.fetch catalog

# 2) 拉已结算市场（可指定联赛）
python -m polymarket.fetch markets --leagues nba nfl epl ucl atp ufc

# 3) 拉历史价格（按成交额排序取前 N 个）
python -m polymarket.fetch prices --limit 3000 --min-volume 50000

# 4) 构建数据集
python -m polymarket.dataset --min-volume 50000 --out data/dataset_tradable.csv

# 5) 校准分析
python -m polymarket.analyze
python -m polymarket.validate     # 受控对照版
```

### 环境变量

| 变量 | 说明 |
|---|---|
| `PM_DATA_DIR` | 数据目录（默认 `polymarket/data/`） |

## 可复用的方法论

这个模块贡献的通用方法，可以直接用在其他市场上：

1. **「只在全部时点都有样本的子集上比较」** —— 消除样本构成偏差
2. **「分档校准」而非「整体均值」** —— 整体均值会被样本构成污染
3. **「每档样本量门槛」** —— 样本 <200 的档位不参与结论
4. **「先验证边际是否覆盖成本，再谈策略」** —— 顺序不能反
