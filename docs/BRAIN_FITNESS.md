# 把 BRAIN 的 Fitness 接进评分系统，并给加密标定换手率地板

> **一句话结论：BRAIN 的 Fitness 公式已经用 24 个 ACTIVE alpha 反推确认过
> （RMSE 0.0033），可以直接复用；但它的换手率地板 `0.125` 是【股票市场的经验值】，
> 不该无脑套到加密上。**
>
> 按「成本/波动」推导，中性假设下**加密地板 ≈ 0.33**。
> 一个 Sharpe 1.6、年化 8%、日换手 0.05 的边缘策略，
> 地板从 0.125 换到 0.33 会让 grade **从 EXCELLENT 掉到 AVERAGE**
> —— 也就是从"可提交"变成"不可提交"。
>
> 全部数字由 `calibrate_floor.py` 在真实数据上产出，原始输出见
> `output_calibrate_floor.txt`。

## 1. 已经确认的东西（不重复造轮子）

`alpha_score.fitness_score()` 里的公式是**反推验证过**的：

```
Fitness = Sharpe × sqrt( |年化收益| / max(0.125, 日换手) )
Margin  = (GP − GL) / GP
```

验证方式：用 **24 个 ACTIVE alpha 的真实 IS 数据**对比候选公式的 RMSE：

| 候选公式 | RMSE |
|---|---|
| `Sharpe·sqrt(\|ret\|/max(0.125, TO))` | **0.0034** ✅ |
| `Sharpe·sqrt(\|ret\|/max(1, TO))` | 0.87 ❌ |

单点验证：MAR（Sharpe 2.14 / 收益 6.63% / 换手 0.2365）→ BRAIN 显示 1.13；
新公式算 **1.133** ✅，旧公式算 0.55 ❌。

**关键含义：换手 < 0.125 完全不扣分；> 0.125 按平方根实打实扣分。**

### 本次新增：BRAIN 官方 `grade` 字段

之前只有本项目的 A/B/C/D/F 分档。但**判断"能否提交"必须看 BRAIN 的 `grade`**，
因为它是**只看 Fitness** 的：

| Fitness | BRAIN grade |
|---|---|
| > 2.0 | EXCELLENT |
| 1.5 ~ 2.0 | **GOOD** ← 用户要求的最低提交线 |
| 1.0 ~ 1.5 | AVERAGE |
| < 1.0 | INFERIOR |

```python
brain_grade(1.99)   # 'GOOD'
brain_grade(1.5)    # 'GOOD'    ← 边界含
brain_submittable(fitness, sharpe)   # 同时要求 Sharpe >= 1.25
```

**为什么要单独实现而不是看页面上的数字**：BRAIN 页面上 Fitness 的**显示值经过舍入**，
在 1.5 边界附近手工分档会出错。真实分级要看 `grade` 字段。

**为什么还要额外卡 Sharpe**：`grade` 只看 Fitness，而 BRAIN 的 IS 检查里
有独立的 `LOW_SHARPE` 门槛（D1 约 1.25）。
**只看 grade 不看 Sharpe，会漏掉一整个失败原因。**

## 2. 核心问题：0.125 是股票市场的常数

`0.125` 是在 **USA / delay1 / TOP3000（股票）** 上反推出来的。加密市场：

| | 股票（BRAIN 假设） | 加密（本项目实测） |
|---|---|---|
| 往返成本 | 10 bps（假设） | **14 bps**（现货 8 + 永续 6） |
| 日波动 | 1.2%（假设，≈年化 19%/√252） | **4.42%**（30 币等权，实测） |
| 年化波动 | ≈19% | **84.4%** |

**加密波动是股票的 3.7 倍，而成本只高 1.4 倍。**

### 推导：地板 ∝ 波动 / 成本

地板的经济含义是「换手低于此水平就不扣分」，即
**换手成本相对于该市场的日均波动可以忽略**。写成不等式：

```
TO × cost ≪ σ        ⟺        TO ≪ σ / cost
```

⇒ **「可忽略」的门槛换手率 = σ / cost**（量纲正好是换手率）。

```
floor_crypto = floor_eq × (σ_crypto / cost_crypto) / (σ_eq / cost_eq)
             = 0.125 × (0.0442 / 14) / (0.012 / 10)
             = 0.125 × 2.63
             = 0.3286
```

### ⚠️ 两个方向都必须小心（本项目的测试第一版就写反了）

| 变化 | σ/cost | 地板 |
|---|---|---|
| 成本 ↑ | 变小 | **↓ 更低** |
| 波动 ↑ | 变大 | **↑ 更高** |

**而且「地板越高」= 对低换手策略【更严厉】，不是更宽容** ——
因为分母是 `max(floor, TO)`：当 `TO < floor` 时分母被抬到 `floor`，Fitness 被压低。

### 加密的直观解释

> 波动高 ⇒ 同样的换手成本相对风险微不足道 ⇒
> 只有换手率**相当高**时成本才开始有意义 ⇒ 可忽略门槛更高 ⇒ 地板更高。

**经济上说得通**：加密的单币波动与信用风险
（见 [`TAIL_RISK.md`](TAIL_RISK.md)：单币最大回撤 96%~99.7%）
远高于股票，长持仓意味着承担了更多风险却未相应调整 —— **不该给"低换手红利"。**

## 3. 地板的**作用方向**：它只影响低换手策略

这是本次最容易搞反、也最值得单独讲的一点（我第一版就搞反了）：

```
分母 = max(floor, TO)
  · TO > floor  →  分母 = TO，地板【完全不起作用】
  · TO < floor  →  分母 = floor > TO → Fitness 比 floor=0 时【更低】
```

**⇒ 地板是给低换手策略设的【惩罚下限】，不是给高换手设的宽容。**

用 carry 实测指标（Sharpe 5.91 / 年化 12.8%）扫描换手，验证这个方向：

| 日换手 | floor=0.125 | floor=0.33 | floor=0.50 | 地板起作用? |
|---|---|---|---|---|
| 0.030 | 16.92 | 6.44 | 4.23 | 是 |
| 0.055 | 16.92 | 6.44 | 4.23 | 是 |
| 0.125 | 16.92 | 6.44 | 4.23 | 是 |
| 0.200 | 10.57 | 6.44 | 4.23 | 是 |
| 0.330 | 6.41 | 6.41 | 4.23 | 是 |
| 0.500 | 4.23 | 4.23 | 4.23 | **否** |
| 1.000 | 2.11 | 2.11 | 2.11 | **否** |
| 2.000 | 1.06 | 1.06 | 1.06 | **否** |

**读法**：换手 1.0 / 2.0（高于所有地板）时三列**完全相同** —— 地板不起作用；
换手 0.03 时三列差异 4 倍 —— 地板完全主导。

**⇒ 修正一个常见误解**：「加密手续费贵，所以更该罚换手」——
方向恰好相反：**因为波动更高，加密反而是【低换手】受到更多惩罚。**

## 4. 地板真正决定 grade 的地方：边缘策略

对高 Sharpe 策略，地板怎么取都无所谓。用 carry（Sharpe 5.91）举例：
地板 0.125 → Fitness 16.9；地板 0.33 → Fitness 6.4（差 2.6 倍）
—— **但两个都是 EXCELLENT，结论不变。**

**地板在【低换手 + 中等 Sharpe】的边缘策略上才是决定性的。**
取一个 Sharpe 1.6 / 年化 8% / 日换手 0.05 的策略：

| 地板 | Fitness | BRAIN grade | 可提交（GOOD+） |
|---|---|---|---|
| 0.125 | 3.620 | EXCELLENT | ✅ |
| 0.200 | 2.263 | EXCELLENT | ✅ |
| **0.329** | **1.377** | **AVERAGE** | ❌ |
| 0.400 | 1.131 | AVERAGE | ❌ |
| 0.500 | 0.905 | INFERIOR | ❌ |

**同一个策略，地板从 0.125 提到 0.33，grade 从 EXCELLENT 掉到 AVERAGE
—— 从"可提交"变成"不可提交"。**

### 这才是标定地板的真正意义

> 加密策略的换手分布与股票不同，用错地板会让**整个筛选队列**发生偏移：
> - **地板取太小（0.125）** → 低换手策略被高估 → **提交一批不够格的 alpha**
> - **地板取太大（1.0）** → 低换手策略被过度惩罚 → **漏掉真正的好 alpha**

对用户现在的目标（只提交 GOOD 及以上）而言，**前者是直接的风险**：
用 0.125 会让一批实际只是 AVERAGE 的 alpha 看起来像 GOOD。

## 5. ⚠️ 诚实交代：这个推导不是无条件稳健

推导的输入里，**股票侧的两个参数（成本 10bps、日波动 1.2%）是假设**，不是事实。
做 3×3 敏感性：

| 股票成本(bps) | 股票日波动 | 加密地板 | 相对 0.125 |
|---|---|---|---|
| 5 | 0.008 | 0.2464 | 1.97× |
| 5 | 0.012 | 0.1643 | 1.31× |
| **5** | **0.020** | **0.0986** | **0.79×** ⚠️ |
| 10 | 0.008 | 0.4928 | 3.94× |
| **10** | **0.012** | **0.3286** | **2.63×** ← 中性假设 |
| 10 | 0.020 | 0.1971 | 1.58× |
| 20 | 0.008 | 0.9857 | 7.89× |
| 20 | 0.012 | 0.6571 | 5.26× |
| 20 | 0.020 | 0.3943 | 3.15× |

**地板落在 0.10 ~ 0.99，其中 8/9 个组合高于 0.125。**

⚠️ **有 1/9 个组合低于 0.125** —— 当股票成本低（5bps）且日波动高（2.0%）时，
推导会给出比 0.125 **更小**的地板。

**⇒ 所以方向【不是】无条件稳健。** 这个推导给出的是**数量级与方向**，不是常数。

**推荐做法**：
- 默认取中性假设下的 **0.33**：`score_factor(..., turnover_floor=0.33)`
- 若只需要方向，表述为「加密地板在 **0.1~1.0** 量级，通常高于 0.125」
- 把假设（股票 10bps / 1.2%）**和结论一起写出来**，别人换假设就能重算
- 在 BRAIN 上调 alpha（股票口径）时**仍然用默认的 0.125**

## 6. 一个被顺手修正的错误认知

我第一版的 `turnover_floor` 文档里写了
「波动越高 ⇒ 地板越低（更宽容）」—— **这是错的**，而且我在测试里
也照这个错误方向写了断言，结果测试失败暴露了它。

正确的链条是：

```
波动 ↑  ⇒  σ/cost ↑  ⇒  成本"可忽略"的门槛更高  ⇒  地板 ↑  ⇒  低换手被罚得更重
```

**这也是为什么这次的测试值得单独写**：`test_higher_vol_raises_floor` 与
`test_lower_turnover_is_penalised_by_higher_floor` 两个断言，
分别锁定了「推导的方向」和「地板的作用方向」。
**没有它们，我会带着一个方向性错误的公式继续用下去** ——
而它在中性假设下算出的 0.33 恰好是"看起来合理"的，不会引起怀疑。

## 7. 顺带确认：Fitness 不是尺度不变的

写测试时顺手发现一个容易误以为成立的性质：

- **Sharpe 严格尺度不变**（分子分母同时 ×k）✅
- 但 `annualized_return` 用的是**几何**平均 `exp(mean(log1p(r))·ppy) − 1`，
  把收益整体放大 k 倍后，几何年化**不是 k 倍**（非线性）
- ⇒ **Fitness 只随尺度单调上升，不成比例**

已写成 `test_sharpe_is_scale_invariant_but_fitness_is_not`：
它同时断言 Sharpe 严格不变、几何年化不是 3 倍、Fitness 单调上升但小于 √3 倍。
**如果哪天有人把 `annualized_return` 改成算术平均，这个测试会失败** ——
而那正是一个需要被注意的行为变更。
