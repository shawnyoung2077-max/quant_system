# 结算恒为 0 的取证链：gamma-api 的 `closed` 默认值陷阱

日期：2026-10-10
影响：**整个纸面实验连续 17 次运行、2 天，一个数据点都没有产出。**
状态：已修复，已用一个真实的 56 笔样本回归验证。

---

## 1. 症状

任务在跑（`LastTaskResult=0`），扫描在产数据，但：

```
运行记录: 17 次
  最近 5 次:
    ... scan  scanned=7004  obs=758   bets=0    settled=0
    ... scan  scanned=7017  obs=880   bets=0    settled=0
纸面下注 100 笔（open=100, settled=0）
```

`n_settled` 恒为 0，而且**不是"比赛还没踢完"**：
数据库里已有 **56 笔注的开赛时间早于当前时间**（最早的 2026-10-09T13:00 UTC）。
按设计它们早该结算。

## 2. 定位

`polytrade/settle.py` 的 `fetch_resolution()` 这样取结果：

```python
j = _get(C.GAMMA + "/markets", {"id": market_id})
```

直接手测（2026-10-10 07:02 UTC，代理正常）：

| 请求 | 返回 |
|---|---|
| `GET /markets?id=5256984` | `[]` ← **空** |
| `GET /markets?id=5256984&closed=true` | 1 条，`closed=True`, `outcomePrices=["0","1"]`, `uma=resolved` |
| `GET /markets/5256984` | 1 条，同上 |

五个已开赛市场全部复现同一模式。

**根因：gamma-api 的 `/markets?id=<id>` 隐式带上 `closed=false`。
市场一旦结算就从该查询里消失，于是 `closed` 永远是 `None`，
`settle_bets()` 把它当成"未到期"跳过。**

```python
if closed is None or not closed or oy is None:
    n_pending += 1
    continue          # ← 已结算的市场永远走到这里
```

注意这不是"慢"，是**结构性恒真**：市场越结算，越查不到。实验永远不会产出数据。

## 3. 修复

`fetch_resolution()` 改为路径式端点，并保留两条退路：

1. `GET /markets/<id>`（主路径，不依赖 `closed` 默认值）
2. `GET /markets?id=<id>&closed=true`
3. `GET /markets?id=<id>`（原写法，仅对未关闭市场有效）

同时加了一个**防误判**分支：作废/取消的市场常返回 `["0.5","0.5"]`，
原逻辑 `1 if v > 0.5 else 0` 会把它判成 YES 输，
**凭空造出一笔亏损**。现在 `|v-0.5| < 1e-6` 直接返回 `oy=None`（不结算）。

## 4. 连带发现的第二个 bug：重复下注

结算跑通后，100 笔里有 **25 笔是同一市场的重复下注，其中 24 笔价位完全相同**。

`scan.py` 的判重条件：

```sql
SELECT 1 FROM bets WHERE market_id=? AND rule_lo=? AND rule_hi=? AND target_lead=?
```

`target_lead` 为 `NULL` 的历史行永远匹配不上（SQL 里 `NULL = 1` 是 `NULL`，不为真），
于是同一市场被重新下注。

实测构成：

```
target_lead 组合      市场数
('1', 'NULL')    ->  23
('3', 'NULL')    ->   2
同价位重复 24 个市场, 不同价位 1 个市场
```

修复：`COALESCE(target_lead,-1)=COALESCE(?,-1)`，保留 1/3/7 天多时点建仓的设计。

**统计后果**：不去重直接按笔算 t 值，有效样本量虚增 70%：

| 口径 | 有效 n | k | SE | t | 95% CI |
|---|---|---|---|---|---|
| 按笔（错） | 56 | −0.1109 | 0.0446 | −2.49 | [−0.1983, −0.0235] |
| 按市场去重 | 33 | −0.1148 | 0.0577 | −1.99 | [−0.2279, −0.0018] |
| 联赛×比赛日聚类 | 12 | −0.1323 | 0.0656 | −2.02 | [−0.2608, −0.0038] |

结论也随之变化：**按笔看是 |t|>2"显著"，去重后是 |t|<2"不显著"。**

## 5. 同类风险点（本次一并加固）

- `digest.py` 的"连续 6 次没下注"告警没有区分**持仓满**与**筛不出标的**，
  把正常的满仓误报成策略失效。已改为先查 `open/MAX_OPEN_BETS` 再决定措辞。
- `report.py` 第 4 节写死的"外部参照价**尚未接入**"已经过期（实际已有 21 行 ref_fair）。
  已改为按实际数据动态输出。
- `report.py` 第 3 节用 `days_to_end`（市场到期日）当持有期，算出 `n = 360 次/年`，
  把 `k*n` 放大成 −16311%。已改为 `settled_ts − entry_ts`（实测 1.19 天）。
- `report.py` 第 2 节校准表用的是**最后一次观测价**（市场关闭后就不再被扫描，
  所以它接近赛前最后时刻，比决策时信息更多）。已加显式口径警告。

## 7. 教训

**"0 条结果"和"没有结果"是两回事。** 一个只返回 0 行的接口查询，
和"实验还没积累够"看起来一模一样。凡是"计数类"指标长期不变，
第一件事是拿一个**已知答案的样本**去手测链路，而不是接受"还没到期"的解释。

本次正是靠"56 笔已开赛"这个已知答案，才把恒 0 拆穿。
