# 一次「Sharpe 25.00」的证伪过程 —— Delta 中性基差套利回测的 bug 定位

> **这是本项目最有价值的一份文档。** 结论本身（"这个 carry 策略 Sharpe 约 5–6"）并不重要；
> 重要的是**从「漂亮得不合理的数字」到「找到它为什么漂亮、并独立验证修正」的完整取证链**。
>
> 面试可讲的一句话版本：
> **我做出一个 Sharpe 25 的策略，我不信它，做了四组可靠性检验，顺着一个逻辑上不可能的现象
> 定位到基差 P&L 的公式错误，写了手算可复现的最小反例，用一条独立计算路径交叉验证了修正，
> Sharpe 从 25.00 掉到 4.95 —— 这才是真实水平。**
>
> 全部数字均由 `_verify_doc_numbers.py` / `_verify_doc2.py` / `_verify_doc3.py` 三个脚本
> 在真实数据上重新计算得到（2559 天 × 30 币，2019-09-10 ~ 2026-09-11），
> 原始输出见 `_doc_numbers.txt`、`_doc_numbers2.txt`、`_doc_numbers3.txt`。

## 1. 起点：一个"太好了"的数字

`carry_v3.py` 做的是 Delta 中性资金费套利：现货多头 + 永续空头，
吃永续资金费。理论上价格风险被对冲掉，只赚资金费。

初始回测结果（默认参数 `min_f=5e-5`，reb14/top15 与 reb28/top30）：

| 配置 | Sharpe | 年化 | 波动 | 最大回撤 | 样本外 Sharpe |
|---|---|---|---|---|---|
| reb14 / top15 | **8.88** | 16.5% | 1.73% | 2.76% | 5.46 |
| reb28 / top30 | **12.06** | 20.9% | 1.58% | 5.08% | 10.88 |

而扫 `min_f` 时（第 3 节详述）出现了 **Sharpe 25.00** 的配置。

**问题不在数字高，而在数字"高得不合理"**：

- 波动率 1.58%，而同期 BTC 波动率是 **60.4%** —— 这个策略的波动只有 BTC 的 **2.6%**。
  一个满仓加密资产的策略，波动是标的的 1/38？
- 样本外 Sharpe 10.88。**样本外 Sharpe 10 在公开市场上不存在。**
- 更根本的：**一个靠"吃资金费"的策略，年化 20.9%，而资金费本身年化只有 8.9%。**
  多出来的 12% 从哪来？

经验上，**加密市场不存在 Sharpe 12–25、波动只有标的 2.6% 的可实现策略**。
要么数据有前视，要么 P&L 记账错了。于是开始系统性地证伪。

> ⚠️ 注意这里的推理方式：**不是"这个数字不可能所以它是错的"**，
> 而是"这个数字与它的收益机制不自洽，所以我要找出记账在哪里出了问题"。
> 前者是主观怀疑，后者是可检验的假设。

## 2. 四组可靠性检验（先排除"运气 / 数据"两类廉价解释）

在做任何代码级排查之前，先跑完四组标准体检。

### 检验 A：尾部拆解 —— 收益靠少数几天撑起来的吗？

剔除最赚的交易日，重算 Sharpe（legacy 口径，reb28/top30）：

| | 原 Sharpe | 剔除最赚 5% 后 | 剔除最赚 1% 后 |
|---|---|---|---|
| reb28 / top30 | 12.06 | **12.71** | **13.19** |

**结论：通过，而且很干净。** 剔除最赚的日子后 Sharpe **不降反升**，
说明收益不是靠少数极端日撑起来的 —— 这是持续性信号该有的样子。

> 反面判据：若剔除后崩塌到 2，说明是运气；若在真实策略上不降反升，
> 也说明是被少数亏损日拖累了。此处"不降反升"幅度很小，属健康状态。

### 检验 B：参数稳定性 —— 是"孤岛"还是"高原"？

扫调仓周期 reb（legacy 口径，top30）：

| reb | 14 | 28 | 40 |
|---|---|---|---|
| Sharpe | 9.61 | **12.06** | 11.75 |

**结论：通过（是高原，不是孤岛）。** 相邻参数不塌陷，极差/均值 = **22%**，
最优值在网格内侧。说明收益是结构性的，不是过拟合某个特定周期。

> 反面教材：14→2.1、28→12.1、40→2.3，那才是典型的过拟合孤岛。
> 注：**我自己第一次手算这个指标时算成了 150%**（把极差当成了比值），
> 后来重新脚本核对才发现是 22% —— 这也是为什么要用脚本核数字，不靠记忆。

### 检验 C：Deflated Sharpe / PSR —— 多重检验惩罚后还活着吗？

一共试了 36 组参数组合。Probabilistic Sharpe Ratio（考虑样本长度、偏度、峰度）：

**PSR = 1.0000**（形式上通过）

**结论：通过但不可信，不作为证据。** PSR 趋近 1 只是被极高的 Sharpe
和约 2559 个观测推上去的，它并**没有真正惩罚 36 次试验**。
在这里 PSR 只是同一个漂亮数字的另一种写法，没有提供新信息。
→ **记录为"形式上通过、实质上无效"**，继续往下查。

### 检验 D：分年度拆解 —— 收益集中在哪个市场状态？

（修正后口径，reb28/top30。修正前口径见第 6 节的对照）

| 年份 | Sharpe | 年化 | P&L 贡献占比 |
|---|---|---|---|
| 2019（部分） | 2.20 | 2.04% | 0.93% |
| **2020** | 8.89 | **22.05%** | **29.70%** |
| **2021** | 12.64 | **36.03%** | **45.74%** |
| 2022 | −0.66 | −0.75% | −1.10% |
| 2023 | 7.24 | 5.37% | 7.76% |
| 2024 | 10.40 | 10.23% | 14.50% |
| 2025 | 1.64 | 1.29% | 1.91% |
| **2026** | **0.33** | **0.53%** | 0.56% |

**2020 + 2021 两年贡献了总 P&L 的 75.4%；2022 年至今只贡献 24.6%。**

**结论：这一条没有通过 —— 但不是 bug 的证据，而是机制性衰减。**

2020–2021 恰好是资金费套利最肥的年份：牛市现货溢价、资金费长期高企、
现货 ETF 尚未落地、做市商还不够成熟。2022 年起（现货 ETF 推进 + 做市商成熟）
资金费被结构性压平，2025 年 Sharpe 1.64、**2026 年只有 0.33**。

→ **这是一个独立的、足以否掉"Sharpe 12 策略"这一说法的结论**：
实盘预期应该按近期年份（0.3–1.6）来估，而不是按全样本。

> **这一条是本次最重要的方法论收获之一**：全样本 Sharpe 极易被某个特定
> regime 主导。**任何策略都必须做分年度 / 分市场状态拆解**，
> 否则你报告的"Sharpe 12"可能只是"2021 年很赚"的另一种说法。

### 四组检验小结

| 检验 | 问题 | 结果 | 是否通过 |
|---|---|---|---|
| A 尾部拆解 | 靠少数几天吗？ | 12.06 → 12.71 | ✅ |
| B 参数稳定性 | 孤岛还是高原？ | 极差/均值 22% | ✅ |
| C Deflated Sharpe | 多重检验后还活着吗？ | PSR 1.0000（但未真正惩罚） | ⚠️ 无效 |
| D 分年度拆解 | 集中在哪个 regime？ | 2020+2021 占 75.4%，2026=0.33 | ❌ |

**四组检验排除了"运气/过拟合/regime"能解释的部分，但没有解释
"资金费年化 8.9%，策略年化却 20.9%"这个核心矛盾。**
→ 说明问题出在**记账**，不在信号。继续查代码。

## 3. 转折点：一个逻辑上不可能的现象

扫 `min_f`（资金费筛选门槛）时，出现了**逻辑上不可能**的排序：

### legacy（旧口径，含 bug）

| min_f（日费率门槛） | Sharpe | 年化 |
|---|---|---|
| **−1.0（不筛，允许负费率）** | **25.00** | 41.0% |
| 0.0（不筛） | 12.82 | 21.7% |
| 5e-5 | 12.06 | 20.9% |
| 1e-4 | 10.32 | 18.5% |
| **5e-4（筛得最严）** | **6.34** | 10.6% |

**"筛得越严，表现越差"** —— 25.00 → 12.82 → 12.06 → 10.32 → 6.34，完美单调递减。

**这在逻辑上说不通**：这个策略的**全部**收益来源就是资金费。
过滤掉低费率和负费率的币，只会让组合的平均费率**更高**，怎么可能变差？

要出现这种现象，必须有一个条件：
**组合里存在一个"另一个收益来源"，而这个来源恰好在被过滤掉的币上更强。**

核对 P&L 分解后，唯一可能的候选就是**基差 P&L**。
→ 顺着这条线查基差记账。

> **方法论要点**：这个反常现象的价值在于 —— 它是**一个不需要看代码就能发现的矛盾**。
> 它把"可能有 bug"从猜测变成了"一定有问题，只要找到它"。
> **回测里出现"参数方向违背经济直觉"时，几乎总是指向记账错误，而不是发现了新 alpha。**

## 4. 代码级取证：逐项排除

### 4.1 费用真的扣了吗？（排除"忘了扣费"）

```python
cost      = Σ_sides dtr × (fee_perp_bps + fee_spot_bps) / 1e4   # 6 + 8 = 14 bps
liq_cost  = Σ liq_flag × liq_fee_bps / 1e4                      # 50 bps 强平费
```

并在单测 `test_costs_are_charged` 中断言：零费率时 `cost == 0`，收费时 `cost < 0`。

**排除 ✔** —— 费用确实扣了。

### 4.2 资金费前视？（最常见的"虚高"来源）

资金费在 t 日结算，但**结算时刻**是否早于 t 日收益？分三种口径重跑（纯资金费，reb14/top15）：

| 口径 | Sharpe |
|---|---|
| 同日结算 `F[t]` | 6.00 |
| 滞后 1 天 | 5.55 |
| 滞后 2 天 | 5.39 |

**排除 ✔** —— 只有约 7% 的差异，不是主因。

> 保守起见，实盘预期应取滞后 1 天口径（5.55）。本文档其余数字按同日口径给出，
> 属于**已知的、已量化的**乐观偏差，约 7%。

**顺带核对资金费数据本身的量级**（这是"数据是否有问题"的检验）：

| 指标 | 实测值 | 是否合理 |
|---|---|---|
| 日均资金费 | 0.000243 | — |
| 折合年化 | **8.9%** | ✅ Binance 永续正常年份在 8–12% |
| 为正的观测占比 | **61.3%** | ✅ 牛市溢价为主，合理 |

**数据本身没问题 ✔** —— 这同时给出了后面推理的关键基准：
**这个策略的资金费收入上限就是年化 8.9%**，而回测报出 20.9%。矛盾坐实。

### 4.3 爆仓后的未对冲暴露？（`unhedged_mode`）

**假设**：强平只可能发生在永续腿，之后现货腿变成裸多，
这段方向性暴露应计入 P&L。旧代码完全不计（`unhedged_mode="ignore"`），
会系统性低估波动率。

**修了，但是个 no-op（空操作）。** 原因：

```python
cooldown_left[blown] = 5     # 爆仓后立刻进入冷却期
...
wt = 0.0                     # 冷却期内权重直接清零
```

强平当天权重就归零了，**根本不存在"裸多暴露"这段状态**。
所以 `unhedged_mode` 改不改结果都一样。

**排除 ✔**（但保留了该开关，因为它把"设计意图"显式写进了函数签名，
且 `unhedged_mode` 当时被怀疑是导致 Sharpe 虚高的原因之一 —— 排查后要留下痕迹，
避免下次重复排查。）

### 4.4 真凶：基差 P&L 的两处错误

```python
# ❌ 旧（legacy）
basis_pnl = -wt * (B[t] - basis_entry)      # basis_entry 钉在"该币首次入场"那天

# ✅ 新（incremental，默认）
basis_pnl = -prev * (B[t] - B[t-1])         # 逐日增量
```

两处**独立的**错误叠加：

**错误 ①：用「今日权重」乘「自入场以来的累计基差变化」**

`(B[t] - basis_entry)` 是一个**累计量**（从入场到今天），
而 `wt` 是**今天的瞬时权重**。两者相乘没有任何金融含义。

数学上正确的写法是把累计量拆成逐日增量后加权：

```
Σ_t −w_t (B_t − B_entry)   ✗  把过去每一天的基差变化都用今天的权重重新计价了一遍
Σ_t −w_t (B_t − B_{t−1})   ✓  权重只作用于它真正持有的那一天
```

**每次调仓权重一变，整段历史基差 P&L 就被新权重重新放大一次。**
调仓越频繁（reb 越小）、权重变化越大，放大越严重。

**错误 ②（更严重，是量级错误的来源）：`net_b[t]` 存的是累计值，却被当作逐日增量 `.sum()`**

```python
net_b[t] = basis_pnl       # legacy 下这是"自入场以来的累计值"
out["basis"].sum()         # 却按"每日流量"求和
```

→ **同一笔 P&L 按持有天数被重复累加。** 持有 30 天，就多算约 30 次。

## 5. 最小复现（Minimal Reproduction）

定位到可疑公式后，**不能直接在真实数据上改代码看结果变没变** ——
那样只能得到"改了之后不一样"，得不到"哪个才是对的"。
必须构造一个**手算得出来**的场景，让正确答案是先验已知的。

```python
# 10 天，2 个币 A/B，基差轨迹完全相同，且线性从 +1% 收敛到 0
# mask 强制 t=0..4 只持 A，t=5..9 只持 B（等价于"同一持仓内部发生权重切换"）
# top_n=1, reb=1, 手续费=0  →  权重每天恒为 1
basis_vals = np.linspace(0.010, 0.0, 10)
```

**手算正确答案**：权重恒为 1，两币基差轨迹相同 ⇒ 等价于连续持有，
telescoping（裂项相消）后

```
correct = −(B_{T−1} − B_0) = −(0 − 0.010) = +0.010000
```

实测：

| 口径 | 基差 P&L | 与手算对比 |
|---|---|---|
| **incremental（新）** | **0.010000** | ✅ 完全一致（8 位小数） |
| **legacy（旧）** | **0.017778** | ❌ 放大 **1.78×** |

**这一步锁死了结论：legacy 是错的，incremental 是对的。**

> 为什么必须做这步：如果没有最小复现，仅仅"改了代码 Sharpe 从 8.88 掉到 4.84"
> 完全可能只是**把策略改坏了**。手算基准是唯一能把"不同"变成"错误"的东西。

## 6. 修正 + 三重验证

### 6.1 真实数据上的影响

| 配置 | 口径 | Sharpe | 年化 | 波动 | 最大回撤 | **OS** | 资金费 P&L | 基差 P&L |
|---|---|---|---|---|---|---|---|---|
| reb14/top15 | legacy | 8.88 | 16.5% | 1.73% | 2.76% | 5.46 | 0.9292 | **0.4732** |
| reb14/top15 | **incremental** | **4.84** | 9.3% | 1.84% | 3.30% | **2.24** | 0.9292 | **0.0233** |
| reb28/top30 | legacy | 12.06 | 20.9% | 1.58% | 5.08% | 10.88 | 0.8537 | **0.6720** |
| reb28/top30 | **incremental** | **5.90** | 10.1% | 1.63% | 2.32% | **4.10** | 0.8537 | **0.0137** |

**看"资金费 P&L"这一列：legacy 与 incremental 完全相同（0.9292 / 0.9292，0.8537 / 0.8537）。**

这是**免费的、天然的对照实验**：`basis_mode` 参数**只影响基差项的计算**，
其他一切都锁死。所以两次运行的差异**只可能**来自基差公式。而差异是：

- reb14/top15：基差贡献 0.4732 → 0.0233（**放大约 20 倍**）
- reb28/top30：基差贡献 0.6720 → 0.0137（**放大约 49 倍**）

**一个"只改了基差记账"的修改，让 Sharpe 从 12.06 掉到 5.90。**
这直接证明：**之前那个漂亮数字的主要来源不是资金费，而是记账错误。**

### 6.2 交叉验证：用一条**独立**的计算路径核对

修完之后不能就说"对了" —— 得让**另一个与回测引擎无关的计算**来验它。

**独立路径**：取回测输出的持仓权重，**等权**、直接累加 Σ(−ΔB)，不碰回测引擎的任何 P&L 代码。

| 计算路径 | 基差 P&L |
|---|---|
| 独立计算的纯基差 P&L（等权，Σ−ΔB） | **+0.0168** |
| 修正后回测输出的基差贡献 | **+0.0137** |

**同号、同阶 ✔。**

> 为什么不是精确相等？因为回测里权重**不等于**等权 —— top_n 选币 + 容量衰减
> 使真实权重逐日变化，且入场时点不同。**能对到同一个数量级，
> 就已经排除了"公式整体错一个量级"这类错误** —— 而这正是我们要验的东西。
> 这也解释了为什么这个检验的判别力是"量级级"而不是"小数位级"：
> 它设计出来就是为了抓 20–50 倍这种错，不是抓 5% 的错。

**这一步是关键**：没有交叉验证，"Sharpe 从 12.06 掉到 5.90"只是一个新数字；
有了交叉验证，它才是一个**被独立证据支持**的数字。

### 6.3 反常现象消失 —— 最强的正确性信号

修正后重扫 `min_f`：

| min_f | legacy Sharpe | **incremental Sharpe** |
|---|---|---|
| −1.0（允许负费率） | **25.00** | 4.95 |
| 0.0（不筛） | 12.82 | **6.01**（最优） |
| 5e-5 | 12.06 | 5.90 |
| 1e-4 | 10.32 | 5.67 |
| 5e-4（筛最严） | 6.34 | 4.29 |

**"越筛越差"的反常消失了。**

legacy 是完美的单调递减（25.00 → 12.82 → 12.06 → 10.32 → 6.34）；
修正后变成 **4.95 → 6.01 → 5.90 → 5.67 → 4.29**，即
**允许负费率最差（4.95，符合直觉），适度筛选后最优，过严筛选变差（4.29）**。

**这是本方法论中最强的一类证据，因为它是一个"事先做出的预测"。**逻辑链：

1. 修正前，我推断"反常的来源是基差 P&L 污染了被过滤掉的币"；
2. 如果这个推断成立，那么**只修掉基差记账后，反常必须消失**；
3. 修掉之后，它**确实消失了**。

> **一个错误的修法几乎不可能恰好让一个无关的反常现象消失。**
> 这比"数字变小了"强得多 —— 数字变小完全可能只是把策略改坏了；
> 而"一个事先未被用于拟合、且事先不知道答案的预测被兑现"，
> 是接近实验科学意义上的确认。

**定量归因（配对消融）**——比较最严筛选（5e-4）相对不筛（0.0）的差异：

| 口径 | ΔSharpe | Δ资金费 P&L | Δ基差 P&L |
|---|---|---|---|
| legacy | **−6.47** | −0.2314 | **−0.4676** |
| incremental | **−1.72** | −0.2314 | **−0.0056** |

**看 legacy 那一行：紧筛导致的损失里，基差项（−0.4676）是资金费项（−0.2314）的 2 倍。**
换句话说，**一个"副产品"（基差记账误差）的波动，比这个策略真正的收益来源（资金费）还大两倍** ——
这在任何正确的记账下都不可能，直接坐实了"反常来自基差污染"这个推断。

### 6.4 修正后的诚实数字（纯资金费，`basis=None`）

| 配置 | Sharpe | 年化 | 波动 | IS Sharpe | **OS Sharpe** |
|---|---|---|---|---|---|
| reb14 / top15 | 6.00 | 8.9% | 1.43% | 7.65 | **2.70** |
| reb28 / top20 | 7.15 | 9.9% | 1.32% | 8.36 | **5.33** |

**注意这个年化 8.9% —— 它和"资金费本身年化 8.9%"几乎完全吻合。**

回到第 1 节的核心矛盾。注意要**同配置对比**（都用 reb14/top15）：

| 口径 | 年化 |
|---|---|
| 资金费本身的机制上限（全市场日均资金费 × 365） | **8.9%** |
| legacy 含 bug 的策略年化 | **16.5%** ← 矛盾：超出机制上限 1.9 倍 |
| 修正后（纯资金费）策略年化 | **8.9%** ← 矛盾消解 |

**修正后的策略年化 = 独立测得的收益来源上限。** ✅

这是整条证据链的**闭环** —— 它把回测输出和一个**通过完全非回测途径**
（直接对资金费面板取均值 × 365）得到的外部事实对上了。
**回测不应该凭空产出超过其收益机制上限的收益**；
修正前超出 1.9 倍，修正后精确落回上限内。

**但即使 6.00 也不是可交付的策略**，因为检验 D 依然成立：
2020+2021 贡献 75.4%，2026 年 Sharpe 仅 0.33。
**样本外 Sharpe 2.70 才是更接近现实的估计。**

## 7. 可复用的方法论

### 7.1 前视偏差检测：改动未来，断言过去不变

```
把 t 日之后的所有价格随机扰动一遍
  → 重跑回测
  → 断言 t 日之前的权重序列【逐位完全相同】
```

**机械可验证，不依赖主观判断。** 见 `tests/test_core.py::TestNoLookahead`（3 个测试）。

### 7.2 样本构成偏差：不同 lead-time 的样本不可比

测 30 天 vs 90 天持仓收益时，30 天口径"更好" —— 但
**30 天口径只覆盖了 15% 的市场**，两个口径根本是不同总体的子集，比较它们等于苹果比橘子。

→ **任何按时间/条件切分的对比，先检查样本量是否可比。**

### 7.3 统计可靠性四检验（本次新增第 4 条）

| 检验 | 问的问题 | 通过标准 |
|---|---|---|
| 尾部拆解 | 收益靠少数几天吗？ | 剔除最赚 5% 后不崩塌 |
| 参数稳定性 | 是孤岛还是高原？ | 相邻参数不塌陷，极差/均值小 |
| Deflated Sharpe | 多重检验后还活着吗？ | PSR 显著**且试错次数被真正计入** |
| **分年度 / 分市场状态** | **收益集中在哪个 regime？** | **无单一年份主导、近期年份仍有效** |

**第 4 条是本次最大的方法论收获。** 全样本 Sharpe 极易被某个特定 regime 主导
（本例：2020+2021 占 75.4%）。**如果只做前三项，这个策略会被误判为"通过"。**

### 7.4 修 bug 的正确顺序（本次最重要的经验）

```
① 发现异常现象（"筛得越严越差" / "收益超过机制上限"）
      ↓  异常 = 存在未知收益来源 或 记账错误。把"可能有问题"变成"一定有问题"
② 逐项排除廉价可能性（费用 ✔ / 前视 ✔ / 未对冲暴露 ✔）
      ↓  每一项都用可复现的对照实验排除，不靠"我觉得"
③ 定位可疑公式
④ 构造最小复现（手算得出的场景）        ← 关键 A：不是"改完看 Sharpe 变没变"
      ↓
⑤ 修正
⑥ 交叉验证（独立计算路径核对）           ← 关键 B：不是"新数字看起来合理"
      ↓
⑦ 检查【事先未用于拟合的预测】是否兑现    ← 关键 C：反常现象消失 = 最强证据
      ↓
⑧ 闭环自洽性检查：修正后的收益 ≈ 独立测得的收益来源上限
      ↓
⑨ 给出诚实结论（含样本外 + 分年度）
```

**三个"关键"是同一个原则：不要让"我改了代码之后数字变好了"成为证据。**
证据必须来自**独立的路径**、**事先的预测**，以及**与收益机制的自洽**。

第 ⑧ 步是本次意外收获的一条额外检验：**修正后的年化（8.9%）与独立测得的
机制上限（资金费年化 8.9%）吻合** —— 这种"闭环"是极强的正确性信号，
因为它把回测输出和外部的、非回测途径得到的事实对上了。

### 7.5 数值纪律：文档里的每个数字都必须由脚本产出

本次教训：我凭记忆写进文档的数字里，**有 5 个是错的**：

| 项目 | 记忆中的值 | 脚本核实的值 |
|---|---|---|
| 初始年化/波动（reb14/top15） | 12.4% / 1.40% | **16.5% / 1.73%** |
| 尾部拆解（剔除最赚 5%） | 12.06 → 9.30（降） | **12.06 → 12.71（不降反升）** |
| 参数稳定性 极差/均值 | 150% | **22%** |
| 日均资金费 / 为正占比 | 0.000267 / 52.8% | **0.000243 / 61.3%** |
| 2020 / 2021 年度 Sharpe | 15.38 / 17.10 | **8.89 / 12.64** |

其中"尾部拆解方向都记反了"最危险 —— 它会把一个**通过**的检验写成
一个看起来**失败**的检验，从而误导整个结论。

→ **纪律：文档里出现的每一个数字，都必须有对应的脚本输出文件可追溯。**
本项目做法：验证脚本统一放在 `docs/verify/`，输出落盘为 `out_*.txt` 一并提交，
文档里每个表格都能追溯到具体一行输出。

复现方式：

```bash
python docs/verify/verify_numbers_1_core.py          # -> out_1_core.txt
python docs/verify/verify_numbers_2_robustness.py    # -> out_2_robustness.txt
python docs/verify/verify_numbers_3_minf_anomaly.py  # -> out_3_minf_anomaly.txt
```

## 9. 这个策略现在值不值得做？

**结论：不值得作为主策略，但值得作为基础设施。**

**1. 收益空间在结构性收窄（不可逆）**

| 年份 | Sharpe |
|---|---|
| 2020 | 8.89 |
| 2021 | 12.64 |
| 2023 | 7.24 |
| 2024 | 10.40 |
| 2025 | 1.64 |
| **2026** | **0.33** |

现货 ETF 落地 + 做市商成熟 ⇒ 资金费被压平。2020+2021 贡献 75.4% 的 P&L，
而 2026 年 Sharpe 只有 0.33。**这不是策略写得不好，是这个套利本身被套利掉了。**

**2. Delta 中性 ≠ 无风险**

本项目已建模：基差风险、爆仓风险、负费率制度风险、容量衰减、双腿手续费。
**尚未建模**的尾部风险：
- 交易所暂停提币（FTX 式）—— 现货腿被锁，对冲失效
- 资金费连续为负（趋势反转制度）
- 永续合约下架 / 结算规则变更
- 现货与永续不在同一交易所时的跨所结算风险

这些是**尾部**，回测里看不到，实盘会一次性把多年收益抹平。
→ 这正是下一步要做"尾部风险建模"的原因。

**3. 真实价值在工程侧**

这套回测框架（前视检测 + 双腿成本建模 + 容量衰减 + 爆仓 + 冷却期 +
**可复现的 bug 对照开关**）是**可复用的**。换任何策略进来，
这套体检流程都能用。**这才是这个项目对求职最有价值的部分** ——
它证明的不是"我会写策略"，而是"我会验证策略，并且不信自己的好数字"。
