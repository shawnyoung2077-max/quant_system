# 那个「第一天回撤 25%」到底是什么

日期：2026-10-10
结论：**它不是回撤，是一个空指标。** 但顺着它查出的仓位缺陷是真的。

---

## 1. 同一个亏损，三个"回撤"

同一笔 $253.62 的亏损：

| 分母 | 报出来的数 |
|---|---|
| 名义本金 $1000（当时配置） | **−25.36%** |
| 名义本金 $3000（改额度后） | −8.45% |
| **实际已结算投入 $560** | **−45.29%** |

**钱一分没变，百分比变了三倍。** 说明当时的指标在数学上是空的 ——
它衡量的不是风险，而是"我随手把本金填成了多少"。

而本金当初就是按 `MAX_OPEN_BETS × STAKE = 100 × 10` 定的，
**等于"全部计划敞口"**。所以只要下满仓，任何亏损都自动除以 100% 本金。

## 2. 它也不是回撤

```
最早开仓 2026-10-09 02:15
最初的 100 笔全部在 42 分钟内开完
然后一起等结算
```

回撤的定义是**净值从高点跌到低点**。这里所有仓位是一次性买入，
时间轴上从来没有过峰值。

而且更根本：**当时系统里一条净值记录都没有**，
所以「回撤」在技术上根本无法测量 —— 能被叫成回撤的，只有那个被误标的分母。

## 3. 但亏损幅度是真的，而且偏大

蒙特卡洛（33 个独立市场、重复下注按同一事件双倍权重、假设市场**完全公允**）：

```
平均收益率   均值 +0.00%   标准差 33.23%
实际观测     -45.29%
P(收益率 <= 实际) = 8.0%
分位 5%/25%/50%/75%/95% = -52.1% / -23.5% / -1.5% / +21.7% / +57.1%
```

约 1/12 的概率。不常见，但**单凭它不足以判定模型坏了**。
（第一次算成 3.8%，是因为错误地假设 56 笔相互独立 —— 把 23 笔重复下注
当成了 23 个独立事件。修正相关性后是 8.0%。）

## 4. 真正暴露出来的缺陷：没有仓位管理

```
最多同时 100 笔 x $10 = 占用本金 100%  ->  本次事件 -45.3% 本金
最多同时  40 笔 x $10 = 占用本金  40%  ->  本次事件 -18.1% 本金
最多同时  20 笔 x $10 = 占用本金  20%  ->  本次事件  -9.1% 本金
```

**同一个事件，只因为敞口上限不同，结果从 −45% 变成 −9%。**

而且这些注高度相关：56 笔里 22 笔来自荷乙**同一轮**。
那不是 100 个独立头寸，而是几个比赛日。

**结论：即使 edge 是真的，这种下注方式也会被一个坏周末打穿。**

## 5. 已实施的修正

### (a) 两道风险闸 —— `config.py`

```python
MAX_EXPOSURE_PCT = 0.20   # 同时在场金额 <= 本金 20%（$600 / 60 注）
MAX_CLUSTER_PCT  = 0.05   # 单个「联赛 x 比赛日」簇 <= 本金 5%（$150 / 15 注）
```

为什么还要按簇限：**按笔限不解决相关性**。22 笔荷乙同一轮，
按笔看是 22 个独立头寸，按簇看是 1 个。只有按簇限才真的在限风险。

闸门在**插入之前**检查，所以不会下超。被拦下时打印
`风险闸拦下: 敞口不足 N 笔 / 单簇超限 M 笔`。

### (b) 净值曲线 —— `polytrade/equity.py` + `equity` 表

```
cash       = 本金 + 已实现盈亏 - 在场敞口
open_stake = 所有 open 注的投入合计（也是最大可能损失）
unrealized = Σ 每笔 open 注 (shares x 当前中间价 - 投入)
equity     = 本金 + 已实现盈亏 + 未实现盈亏
peak       = equity 历史最高
drawdown   = equity / peak - 1
```

未实现盈亏取该市场**最后一次观测**的中间价；没有观测的用入场价顶替，
并报告有多少笔是顶替的（`n_unreal_fallback`），避免悄悄乐观或悲观。

`equity.snapshot()` 在每次运行**结算之后**调用 —— 顺序不能反，
否则已实现盈亏还没更新。

### (c) 报告口径 —— `report.py` / `digest.py`

把三个分母**并列**印出来，并标明哪个可以和 edge 挂钩：

```
【口径必须分清】同一笔亏损在不同分母下差很多：
   已结算投入              $   560.00
   已结算盈亏              $  -253.62
   ★ 对已投入资金的收益率     -45.29%   <- 只有这个能和 edge 挂钩
   占名义本金                  -8.45%   <- 仅供参考，**不是回撤**
```

并且：**快照不足 3 天时明确写"最大回撤还测不了"**，而不是编一个数。

## 6. 当前状态（修正生效后）

```
本金 $3000   在场敞口 $1020（34.0%）  ← 超过 20% 上限，新注已被闸门挡住
已实现 $-253.62   未实现 $-39.33   净值 $2707.06
最大回撤：暂不可测（只有 1 个快照日）
```

敞口超限是**预期行为**：$1020 里有 $520 是 12–24 小时内的注，明天就结算，
敞口会自然回落到 $600 以下，新注恢复。**闸门不需要人工干预。**

## 7. 教训

**报告里每一个百分号都必须写清分母。**

这次的问题不是算错，而是**算对了但没写清在对什么**——
同一个数字既能读成"稳健的 8%"也能读成"离谱的 25%"，取决于分母，
而读者默认会挑最吓人的那个理解。

配套的一条：**没有净值序列，就不该出现"回撤"这个词。**
要么给出可复算的定义，要么明说测不了。
