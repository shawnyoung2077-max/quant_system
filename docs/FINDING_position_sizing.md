# 仓位与偏差门槛：把日波动从 5.8% 压到 1.3%

日期：2026-10-10
起因：用户质问「你觉得我会投资一个一天涨跌幅 8% 的投资品吗？」
结论：**不该投。** 那是仓位设计错误，不是市场问题。已按目标反推重设。

---

## 1. 8% 是哪来的

第一轮的配置是 `MAX_OPEN_BETS=100 × STAKE=$10`，本金 $3000。
也就是**一天之内把 0.33 倍本金全部押出去**，而且都押在同一批联赛、同一个周末。

日盈亏标准差可以精确写出来：

```
单注收益率标准差  per = 2.24          （在 0.16~0.29 的买入价上实测）
日盈亏标准差     SD  = per × stake × sqrt(当日结算注数)
                     = per × sqrt(stake × 日投放)      （因为 注数 = 投放/stake）
```

注意这个式子的形状：**波动率由 `stake` 主导，不是由投放比例主导。**
投放翻倍只让 SD 变成 √2 倍，但 stake 翻倍会让 SD 变成 √2 倍的同时注数减半。

实算（本金 $3000）：

| 日投放上限 | 单注 | 注数 | 日盈亏 SD | 占本金 |
|---|---|---|---|---|
| **20%** | **$10** | 60 | **$173** | **5.78%** ← 原配置 |
| 20% | $5 | 120 | $123 | 4.09% |
| 20% | $2 | 300 | $78 | 2.59% |
| 10% | $10 | 30 | $123 | 4.09% |
| 10% | $2 | 150 | $55 | 1.83% |
| **5%** | **$2** | 75 | **$39** | **1.29%** ← 现配置 |
| 5% | $1 | 150 | $27 | 0.91% |

一次 2.5σ 就是 14% —— 用户看到的 8% 只是一次 1.4σ 的日子。

**所以问题不是"运气差"，是仓位大了 4 倍。**

## 2. 现在的三道闸（本金 $3000）

```python
STAKE             = 2.0     # 每注 0.067% 本金
MAX_DAILY_NEW_PCT = 0.05    # 日投放 <= $150      <- 用户明确要求的
MAX_EXPOSURE_PCT  = 0.10    # 同时在场 <= $300
MAX_CLUSTER_PCT   = 0.02    # 单个「联赛 x 比赛日」簇 <= $60
```

加**簇上限**是因为按笔限不解决相关性：第一轮 56 笔里 22 笔来自荷乙同一轮，
按笔看是 22 个独立头寸，按簇看是 1 个。只有按簇限才真的在限风险。

## 3. 偏差门槛：原来的规则根本不是"偏差"

用户要求「限制在偏差较大的时候才交易」。而原规则是
`价格落在 [0.15, 0.30) 就买 YES` —— 那是**价格区间**，不是偏差。
同一个区间里，偏差可以从 −14.5pp 到 +31.4pp。

### 偏差能估到多细？—— 这是决定性的实测

**先试「联赛 × 0.03 宽价格细档」**（`build_edge_cells.py`）：

```
356 个单元格，其中 n>=40 的只有 28 个
按市场聚类 bootstrap + BH 多重比较校正后：
    gross ci_low > 0 的      7 / 28
    q_bh < 0.05 的           0 / 28
    三项同时满足             0
```

**显著的单元格一个都没有。** 在这个分辨率上设门槛就是编数字。

**退到「只按联赛」就成立**（26 个联赛 n>=40）：

| 联赛 | n | 净偏差（扣费扣价差） | t |
|---|---|---|---|
| A-League Men | 39 | +32.7pp | — |
| Chinese Super League | 63 | +24.1pp | 4.03 |
| EFL Championship | 63 | +22.5pp | 3.83 |
| MLS | 70 | +21.7pp | 3.90 |
| Primeira Liga | 32 | +21.6pp | — |
| Brasileirão Série A | 102 | +19.7pp | 4.33 |
| Süper Türkiye | 59 | +13.8pp | 2.43 |
| Bundesliga | 208 | +8.7pp | 3.22 |
| FIFA Friendlies | 159 | +7.7pp | — |
| **Premier League** | 319 | **+4.5pp** | 2.44 ← 未过 5pp 门槛 |

**所以门槛只能设在联赛层。这是数据分辨率的事实上限，不是偷懒。**

### 口径

```
net_bias = gross_bias - 0.05×p×(1-p) - 0.0087
           └ 历史偏差   └ 官方 taker  └ 实测半价差
```

那 0.0087 是本项目实测的「成交价 − 当时中间价」均值。
必须扣：历史 price 来自 CLOB `/prices-history`（成交/中间价），
而我们下单付的是 ask。不扣这一项，"偏差"就是虚的。

### 实现里的一个坑（我自己写的）

第一版 `track_of` 只比较 `net_bias >= MIN_EDGE_PP`，**忘了同时要求 `supported=1`**。
结果 n_band=1 的联赛（只有一个历史市场）会被判成 `valid` ——
比如「法国超级杯」用**单个市场**算出 +79.7pp 的"偏差"。

那是噪声，不是证据。修正为：**supported 是"偏差是否存在"的条件，不是额外过滤器。**
偏差只有在能显著估计的地方才存在。

## 4. 双线额度重新分配

`valid` 占 90%，`explore` 占 10%。

为什么 explore 只给 10%：它的定义就是**估不出偏差**的联赛，严格说它不该占投资额度。
留一条象征性额度是为了 (a) 测这些市场的真实滑点，(b) 作对照组。

**关键：探索这些联赛所需的证据不来自下注，而来自 `observations` 表。**
历史那套偏差结论就是从「某时点价格 + 最终结果」算出来的，
而 observations 每个快照都记录了 bid/ask/mid 和最终结算，
**无论我们有没有下注**。所以限制 explore 的下注额度不会削弱证据积累。


敞口 $1020 是**存量**（旧的 $10 注），会随结算自然回落 —— 不需要人工干预。

## 6. 教训

**波动率不是"运气"，是可以先算出来的。** `SD = per × √(stake × 日投放)`
在手，就不该等到亏了 25% 才发现仓位大了 4 倍。

配套的第二条：**在数据不支持的分辨率上设门槛，等于编一个数字。**
「联赛 × 价格细档」看起来更精确，实际 BH 校正后一个显著都没有 ——
精确到没有证据，比粗糙但有证据更危险。
