# 横截面中性化 / 截断 / 归一化：给 carry 装上 BRAIN 的后处理链，结果它把 alpha 拿掉了

> **一句话结论：在 Delta 中性资金费套利（carry）上，中性化不但没用，而且是统计显著的负面。**
>
> 这不是"框架没做出来"，而是**框架做出来了并证明了这个方向不该走** ——
> 与此同时它顺手发现了 BRAIN 截断流水线的两个数学性质（等权下截断是恒等变换、
> cap < 1/n 时约束不可行），这两条是可以直接迁移到 BRAIN 打 alpha 的。
>
> 全部数字由 `run_neutral_carry.py` 在真实数据上产出（2559 天 × 30 币，
> 2019-09-10 ~ 2026-09-11），原始输出见 `output_neutral_carry.txt` 与
> `output_neutral_carry_signif.csv`。

## 1. 做了什么

新增两个模块：

| 文件 | 内容 |
|---|---|
| `neutral.py` | BRAIN 式后处理原语 + 加密分组工具 |
| `run_neutral_carry.py` | 把原语施加到真实 carry 组合上并做归因与显著性检验 |

### `neutral.py` 提供的原语（对齐 BRAIN 的真实流水线顺序）

```
表达式 → pasteurize → decay → 【中性化】 → 【截断】 → 【归一化】 → ×$20M → 持仓
                                  ↑            ↑           ↑
                              本模块       本模块      本模块
```

| 函数 | 作用 |
|---|---|
| `truncate_weights(w, max_weight)` | 单名权重上限，保号：`w_i ← sign(w_i)·min(\|w_i\|, cap)` |
| `normalize_weights(w)` | `÷ Σ\|w\|` → 毛暴露 = 1（**除以 Σ\|w\| 而非 Σw**：多空组合 Σw=0，除以它会爆炸） |
| `cap_and_normalize(w, cap)` | **硬上限**版：保证最终 `\|w_i\| ≤ cap` |
| `neutralize_groups(w, groups, mode)` | 分组中性化，`mode ∈ {demean, pair, rank}` |
| `neutralize_beta(w, betas)` | 净 Beta → 0（缩放空头腿） |
| `brain_pipeline(...)` | 按 BRAIN 顺序串起来 |
| `size_buckets(adv, n)` | 按成交额分档（市值代理，⚠️ 见下） |
| `beta_buckets(prices, n)` | 按滚动 BTC-beta 分档 |
| `sector_panel(...)` | 30 币板块标签面板（⚠️ 静态映射，见下） |

**分组中性化的三种语义**（这是本次新增的、可复用的核心）：

| mode | 做法 | 含义 |
|---|---|---|
| `demean` | 组内去均值 | 剥离"该组整体被看多/看空"的绝对暴露。**每组净暴露 0 ⇒ 全组合 Σw=0，天然 dollar-neutral** |
| `pair` | 组内按大小分上下两半，上半 +、下半 − | 只交易组内相对排序，彻底剔除组的整体方向 |
| `rank` | 组内截面秩变换到 [−1,1] | 抗极值（funding 率有厚尾） |

### 两个必须写进代码的诚实局限

1. **没有真实市值面板**。历史流通量数据本项目未采集，用 **ADV（美元成交额）作市值代理**。
   ADV 与市值高度相关但不等于市值，且**流动性本身会被策略影响**。
2. **`SECTORS` 是静态手工映射**。真实板块归属随时间变化（INJ 从 DeFi 转向 L1、
   ARB/OP 常被归入 L1 板块）。用今天的板块映射划分历史 = **轻度前视偏差**。
   本处用于"分组中性化"，影响远小于选股，但必须知道它存在。

## 2. 先修一个我自己的 bug：自校验没对齐

按本项目纪律，新引擎必须能和已有引擎对账。第一次对账**失败了**：

```
本脚本基线            Sharpe=7.03 年化=12.40%
carry_v3（basis=None） Sharpe=6.00 年化=8.94%
```

差 1.03 Sharpe / 3.5pp 年化。原因不是经济模型错了，而是**比的东西不一样**：
本脚本的 P&L 引擎**不含爆仓/冷却期**（那部分与中性化正交，单独研究），
而 `carry_v3(leverage=2.0)` 会强平。

查 `carry_v3` 发现 `leverage` **只用于算强平线**：

```python
liq_line = max(0.02, 1.0 / leverage - maint)      # 仅此一处用到 leverage
```

于是取 `leverage=0.1` → `liq_line ≈ 9.995`（需涨 1000% 才强平）⇒ 等价于关闭爆仓。对账通过：

| | Sharpe | 年化 |
|---|---|---|
| **[A]** `carry_v3` 爆仓**关闭**（lev=0.1） | 6.99 | 12.29% |
| **[B]** 本脚本基线 | **7.03** | **12.40%** |
| A vs B 差异 | **0.04** | 0.11pp → **对齐 [OK]** |
| **[C]** `carry_v3` 爆仓**开启**（lev=2.0，项目正式设置） | 6.00 | 8.94% |

### 副产品发现：爆仓+冷却期每年吃掉 3.35 个百分点

C vs A：**年化 12.29% → 8.94%，差 3.35pp/年**。

机制：2× 杠杆下 Delta 中性腿**仍会被强平**（现货腿上涨触发永续腿保证金不足），
强平后进入 5 天冷却期、权重直接清零 —— **等于白丢 5 天资金费收入**。

这是一个独立的、之前没被量化的成本项。而且它说明：
**"Delta 中性"并不等于"安全"**，杠杆仍然在制造强平事件。

## 3. Q1 截断：两个数学性质，一个实证结论

### 性质 1 —— 等权组合上，「截断 → 归一化」是**恒等变换**，与 cap 无关

实测：等权 long-only top15 组合，cap = 0.20 / 0.10 / 0.07 / 0.05，
BraIN 顺序变体的 Sharpe **全部等于基线 7.03**，逐日收益序列**完全相同**
（显著性检验里被标为「完全相同」的 4 个变体）。

一开始我以为是代码 bug，实测 `truncate_weights` 单独跑没问题（最大逐点差异 0.95）。
真正的解释是数学：

> 某日持 n 名、每名 1/n。
> - 若 `cap ≥ 1/n`：**完全不触发**，输出 = 输入。
> - 若 `cap < 1/n`：全体被压到 cap，`Σ = n·cap`；归一化 `÷ n·cap` ⇒ 每个**又变回 1/n**。
>
> **两头都回到原点。**

⇒ **截断只在权重本来就不等时才有意义。** 一行都改成同一高度，再等比缩放，
等于什么都没做。这解释了一个非常容易被误读成 bug 的现象。

### 性质 2 —— `cap < 1/n` 时，「Σ|w| = 1 且 |w_i| ≤ cap」**不可行**

n 名最多承担 `n·cap` 的毛暴露，达不到 1。实测不可行交易日占比：

| cap | 不可行交易日占比 |
|---|---|
| 0.10 | 20.8% |
| 0.07 | 46.9% |
| 0.05 | **94.7%** |

朴素的「截断 → 归一化」迭代会停在**不动点却不满足上限**（归一化每次都放大回 1/n），
所以 `cap_and_normalize` 在不可行时**按 cap 等比缩小总暴露**（剩余留现金），
保证 `|w_i| ≤ cap` 严格成立，同时诚实承认 `gross < 1`。

### 实证结论：strict 截断的"改善"是仓位管理，不是 alpha

| 变体 | Sharpe | 年化 | 波动 | 平均毛暴露 | OS |
|---|---|---|---|---|---|
| 0 基线 long-only | 7.03 | 12.40% | 1.66% | 0.978 | 4.84 |
| 1a strict 截断@0.10 | 7.17 | 12.2% | 1.60% | 0.893 | 5.72 |
| 1a strict 截断@0.05 | **7.48** | **9.0%** | 1.15% | **0.632** | 6.74 |

Sharpe 7.03 → 7.48 看起来是改善，但 **年化从 12.37% 掉到 8.98%（−3.4pp）** ——
这是**拿收益换波动**的杠杆权衡，不是 alpha 改进。

**归因检验**：把基线收益按 strict 的**逐日毛暴露比例**重新缩放，得到：

```
base Sharpe              = 7.03
base × 逐日缩放 Sharpe    = 7.14   ← 纯粹的时变仓位效应
strict 实际        Sharpe = 7.48
两者逐日相关系数 = 0.9941   最大逐点差 = 0.00098
```

⇒ strict 截断的收益序列与**纯粹的仓位缩放**99.4% 无法区分。
再按年份看，`cap=0.05` 把 **2019 年毛暴露压到 0.038（仅原 6%）** ——
早期币少、集中度高，被缩得最狠。

**所以：strict 截断的本质是时变仓位管理，与跨截面选币无关。**

## 4. Q2 分组中性化：**显著有害**

45 个变体全部做了**配对 t 检验**（对同一批日期的收益差，而不是比较两个独立的 OS Sharpe）：

```
显著改善 = 9   显著恶化 = 22   无差异 = 4   噪声 = 10   （共 45）
```

### 显著改善的（按年化效果排序）

| 变体 | ΔSharpe | 年化效果 | t |
|---|---|---|---|
| 2A 信号rank(BTC-beta3档) | +0.11 | **+0.54%** | 3.53 |
| 2A 信号rank(市值代理3档) | +0.08 | +0.51% | 3.63 |
| 2A 信号rank(市值代理5档) | +0.02 | +0.48% | 3.57 |
| 1b 信号加权+截断@0.10(BRAIN) | −0.04 | +0.22% | 4.08 |

最好的也只有一个 **+0.54%/年**。在一个年化 12.4% 的策略上加半个百分点 ——
**统计显著，经济微小，不改变任何结论。**

### 显著恶化的（最严重）

| 变体 | ΔSharpe | 年化效果 | t |
|---|---|---|---|
| 3B 权重pair(板块) | −5.46 | **−10.57%** | −19.73 |
| 3B 权重demean(板块) | −2.86 | −8.24% | −18.69 |
| 3B 权重demean(BTC-beta3档) | −2.80 | −8.33% | −16.37 |
| 3B 权重demean(市值代理3档) | −2.74 | −8.32% | −16.05 |

**真正的多空中性化（组内 demean，净暴露 = 0）把策略打崩了：**
OS Sharpe 从 4.84 掉到 **−0.15 ~ −1.19**，年化效果 **−7.4% ~ −8.3%**，t 值 **−13 ~ −19.7**。

而 `3B 权重pair` 更值得警惕：**IS Sharpe = 8.90，OS Sharpe = 1.49** ——
巨大的样本内/样本外鸿沟，是典型的「样本内拟合出来的假信号」形态。

### 经济解释：中性化拿掉的正是 alpha 本身

**carry 的收益是「多头风险溢价」，不是截面价差。**

> 资金费为正 ⟺ 永续多头拥挤 ⟺ 你作为空头在**收租**。
> 把它做成 dollar-neutral（组内去均值）= 同时做多高费率、做空低费率，
> 而**空头腿在倒付资金费** —— 净额把整块溢价抹掉，只剩噪声。

**中性化不是免费的。** 它剥离"组整体暴露"的同时，
也剥离了"组整体的风险溢价" —— 而在 carry 上，那块溢价就是全部收益。
这一点在股票上通常不成立（行业中性化确实能提升 IR），
**但在一个"收益本身就是某个方向暴露的补偿"的策略上，中性化是自残。**

## 5. Q3 BTC-beta 中性化：对 carry 是**严格恒等变换**

实测权重**最大逐点差异 = 2.78e-17**（纯浮点噪声），Sharpe 7.03 → 7.03。

原因很清楚：

> carry 每一名都是「现货多 + 永续空」，**价格 Beta 天然为 0**。
> weights 里根本不含方向性暴露 —— **没有 beta 可中性化。**
> （`neutralize_beta` 只缩放空头腿，long-only 时缩放系数 k 恒为 1。）

**推论：在 carry 上提"做 beta 中性化"这个需求本身就是错的。**
正确的中性化对象是 **funding 暴露** —— 而这正是组内 `demean` 在做的事，
而第 4 节已经证明那个反而有害。

> 这一条的价值在于：它把一个**听起来很专业的需求**验证成了恒等变换。
> 面试时这比"我做了 beta 中性化"强得多 —— 因为我能说清**为什么它在这个策略上无意义**。

## 6. 一个必须讲的统计学纪律

第一次跑显著性检验时，我把 4 个「与基线完全相同」的变体算出了 **t = 9.65**，
标记为"显著改善"。这是假显著：

> 对**几乎相同**的两条序列做配对 t 检验，分母 `std(d)` 会趋近浮点噪声级，
> t 值被放大成任意大的数。

修正：先判 `max|d|`，浮点噪声直接归为「完全相同」，不给 t 值。

**更大的纪律问题**：样本外只有 **1024 天（2.8 年）**，而

```
SE(Sharpe) ≈ sqrt((1 + 0.5·SR²) / T)
```

在 SR ≈ 5、T = 2.8 年时 **SE ≈ 2.13** —— 也就是说
**"OS Sharpe 相差 2 以内根本分不出高下"**。

所以：
- 上面所有"最优变体"的 OS Sharpe 排序（6.74 vs 5.29 vs 4.84）**不能直接信**；
- 必须用**配对 t 检验**（同一批日期的收益差），并同时报**经济效果**（年化效果%）；
- **统计显著 ≠ 有用**。`+0.54%/年` 的 t 值 3.53 是显著的，但它不改变结论。

## 7. 结论与后续

| 问题 | 结论 |
|---|---|
| Q1 截断对 carry 有用吗？ | 等权下是**恒等变换**（数学性质 1）；strict 版有效但本质是**时变仓位管理**（99.4% 与纯缩放无法区分），且 **年化 −3.4pp** |
| BRAIN 顺序 vs 硬上限？ | **语义不同**。BRAIN 顺序约束的是归一化**前**的权重，最终可超上限；硬上限需迭代，且 `cap < 1/n` 时**不可行**，必须缩总暴露 |
| Q2 分组中性化能改善吗？ | **不能，且显著有害。** 唯一的正项只有 +0.54%/年；真多空（demean）年化 −7.4% ~ −8.3%，t = −13 ~ −19.7 |
| Q3 beta 中性化是 no-op 吗？ | **是，严格恒等变换**（差异 2.78e-17）。carry 无价格方向暴露 |

**总结：截断是恒等变换；分组中性化显著有害；beta 中性化是恒等变换。
在 carry 上，什么都不做就是最好的做法。**

**但这不代表 `neutral.py` 没价值**，它有三重价值：

1. **可迁移**：`neutralize_groups` / `truncate_weights` / `normalize_weights`
   正是 BRAIN 后处理链的原语，可以直接用于 BRAIN alpha 构建
   （BRAIN 的行业中性化、subindustry 中性化就是 `demean`）。
2. **证明了不该做什么**：省下了把中性化写进 carry 生产代码的时间，
   而且理由是**统计显著的实证**，不是"我觉得没用"。
3. **两个数学性质**（等权截断恒等、`cap < 1/n` 不可行）是**跨策略通用**的，
   在 BRAIN 上一样成立 —— 因为 BRAIN 的 truncate/normalize 就是这两个操作。

### 后续

- **把中性化用在它该用的地方**：一个有**方向性**暴露的加密 alpha
  （横截面动量 / 反转），那里 beta 中性化不是恒等变换，才可能真的改善风险调整收益。
  `neutral.py` 的原语已经就绪。
- **BRAIN 侧**：用 `neutralize_groups` 复现 BRAIN 的 industry/subindustry 中性化，
  对齐官方语义后接入 `alpha_score`。
- **尾部风险建模**（原计划的 B）：资金费符号连续翻转、交易所提币暂停、基差暴走。
- **爆仓成本独立量化**：本次副产品发现 3.35pp/年，值得单独做成一个研究题目
  （降杠杆 vs 延长冷却 vs 提高强平缓冲，哪个最优）。
